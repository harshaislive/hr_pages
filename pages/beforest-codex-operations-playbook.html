02 / What Codex is

Codex explained simply

What is Codex?

Codex is a work assistant inside a chat. You type a message. It can read connected work tools, make a list, write a draft, or carry out an approved change.

You do not need to know code. You can write: “Show me my open Zoho tasks,” or “Find this email and draft a reply.” Codex reads the tool and explains what it found.

For Beforest, Codex reaches Zoho Projects and Gmail through Maton. Think of Maton as a safe connector. It carries the request to the right work account.

Codex does not need to change anything immediately. The safest first request is always: read it, make a list, and do not change anything.

First, ask Codex to show you what is there. Then decide what to do.
Simple rule 01

Ask it to look.

Codex reads the current tasks or email thread. Nothing changes yet.

Simple rule 02

Add your notes.

Tell Codex which task is done, which date is wrong, or which email needs a reply.

Simple rule 03

Ask it to check.

After an approved change, Codex opens the record again and tells you what Zoho or Gmail now shows.

06 / What Maton does

One simple explanation

Maton connects Codex to our work tools.

Codex understands the request. Maton safely carries it to Zoho Projects or Gmail. The final task and email still live in Zoho and Gmail.

What the employee does

Ask a question. Read the answer. Add notes. Approve the exact task change or email.

Maton / safe connector

What the tools do

Zoho stores the task. Gmail stores the email. Codex checks both after the approved action.

You explain the work. Codex and Maton handle the tool steps.

You do not need to know connection IDs, API names, or computer code. Say what you want in normal work language.

Good examples are: “Show me what is overdue,” “Explain this task,” “Write a reply but do not send,” and “Check that the change happened.”

08 / Four simple safety rules

Remember these

Reading is not the same as changing.

Codex can look and prepare work first. A task update or email send should happen only after the target and action are clear.

1
Start by reading

Add “Do not change anything” to the first request.

2
Name the right place

Say which project, task, email sender, or subject you mean.

3
Approve the action

“Write a draft” does not mean “send it.” “Show tasks” does not mean “close them.”

4
Check after changing

Ask Codex to reopen the task or sent email and show you the final result.

5
Look for duplicates

Before creating a new task, ask Codex whether a similar task already exists.

6
Stop when something looks wrong

Ask Codex to explain the problem. Do not keep clicking or sending.

Can Codex update every overdue task automatically?

Yes, but first ask Codex to make the list. Add your notes to the tasks. Check the proposed changes. Then approve only the clear ones.

Can I ask Codex to send an email immediately?

Yes, if the sender, recipients, thread, body, and attachments are already exact and you explicitly authorize the send. For most work, drafting first gives the team a useful approval checkpoint.

What happens when Zoho rejects a change?

Codex reads the error and explains it. This morning, one main task got its date from a smaller task. Codex updated the smaller task and checked that the main task date changed too.

Where should completed work be recorded?

Keep the final update in Zoho. Close or update the task there. Add a comment or document when someone may need the reason later. Then ask Codex to check it.
